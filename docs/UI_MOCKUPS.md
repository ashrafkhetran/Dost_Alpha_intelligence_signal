# UI mockup descriptions

## 1. Overview — intelligence cockpit

Dark canvas, quiet violet/cyan accents, no decorative ticker that suggests a live feed
when it is not live. The header shows topic scope and a precise last-updated state. The
main column holds prioritized, evidence-rich signals; the secondary column contains a
short morning brief and explicit "what to verify" context. Metrics are real and dated,
or omitted. A single primary action starts a briefing.

## 2. Intelligence feed — scanning and verification

Compact search/filter toolbar with visible active filters. Each card prioritizes
headline, source/date, interpretation, then impact/confidence definitions. A detail
drawer reveals source count and original documents, with primary sources distinguished
from commentary. Save/watch controls have accessible labels and visible confirmation.

## 3. Trend radar — measured momentum

Replace an unexplained radar polygon with a selectable time-series or ranked topic view
that exposes its evidence window, sample size, growth baseline, and confidence. Provide
a sortable table and non-visual summary. If there is insufficient data, say so rather
than inventing a score.

## 4. AI Analyst — cited research workspace

Prompt box includes topic and time scope. A response begins with evidence coverage and
retrieval timestamp. Claims carry numbered source references; clicking reveals the
exact supporting excerpt and publisher. An uncertainty panel separates missing evidence
and contradictory findings. Provider/sample/error states are visually unmistakable.

## 5. Executive Briefings — authoring surface

Choose format, audience, and reporting window; inspect source coverage before generation.
Show title, executive summary, evidence-linked developments, implication, risks, and
actions. Let users review before export, retain provenance in output, and show clearly
which portions are generated.

## 6. Subscription — capability-led conversion

Use a focused comparison table, not pressure tactics. Each plan states price/interval,
limits, renewal and cancellation behavior. Explain an upgrade in the context of a
requested feature. Enterprise requests are a contact flow until team access and support
exist.

## Shared states

- **Loading:** describe the operation and retain context.
- **Empty:** explain how to add topics or broaden scope.
- **Stale:** state last successful refresh and what is missing.
- **Partial:** expose failed sources and avoid implying full coverage.
- **Error:** explain retry/support action without hiding provider failure.
- **Sample:** conspicuous illustrative-data banner on all screens.
